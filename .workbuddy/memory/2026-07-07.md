# 2026-07-07 工作日志

## JNI 0.22.3 编译错误修复

### 问题
- jni crate 0.22.3 中 `Env` 不是 FFI 安全的，不能用于接收 JVM 传递的 JNIEnv*
- 之前已将所有 JNI 函数改为 `EnvUnowned` + `with_env()` 模式
- 但出现 14 个编译错误：`resolve::<ThrowRuntimeExAndDefault>()` 要求 `T: Default`，而 `*mut _jobject`（jstring/jobject）不实现 Default

### 修复策略
- 对于返回原始指针类型（jstring/jobject）的函数：`with_env` 闭包返回 `Result<JObject<'_>, Error>`（JObject 实现了 Default）
- 使用 `.resolve::<ThrowRuntimeExAndDefault>().into_raw()` 替代原来的 `.resolve::<ThrowRuntimeExAndDefault>()`
- 对于返回实现了 Default 的类型（jlong/bool/jint/f32/() 等）：不需要修改
- 辅助函数 `string_to_jstring` 改为返回 `Result<JObject<'local>, String>`，需要显式生命周期标注
- 辅助函数 `entry_to_jobject` 改为返回 `JObject<'local>`，需要显式生命周期标注
- 闭包内 null 返回用 `JObject::null()` 替代 `std::ptr::null_mut()`
- JString/JByteArray 转换：`unsafe { JObject::from_raw(env, s.into_raw()) }`

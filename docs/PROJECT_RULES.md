# Living Agent Service 项目规则（核心框架守护）

> 目的：保证后续开发不脱离核心框架；本文件是架构约束与评审基线。

## 1. 总体规则

1. 任何新增功能必须映射到既有分层：接入/认知/执行/知识进化/安全治理/基础设施。
2. 任何跨模块改动需说明“影响域 + 回滚路径 + 验证方式”。
3. 禁止为赶进度绕过核心抽象（如绕过权限检查直接调用大脑）。

## 2. 架构规则

1. Brain 只通过 `BrainContext` 获取运行依赖，不直接耦合基础设施实现。
2. 外部系统接入统一走 Tool/Skill/Adapter，不在 Brain 内写平台SDK逻辑。
3. 通道通信使用 `ChannelMessage` 标准结构，不自定义隐式协议。
4. 新增模块必须明确归属领域（brain/employee/knowledge/evolution/security/channel）。

## 3. 员工模型规则

1. 必须复用统一 `Employee` 抽象。
2. 数字员工新增能力必须归入编制（Fixed Definition）并注明边界。
3. 员工状态迁移必须可校验，不允许无约束“强制跳转”。

## 4. 知识系统规则

1. 所有知识写入必须声明作用域（L1/L2/L3）。
2. 知识条目必须附带元数据（至少：type/domain/timestamp/source）。
3. 禁止将未经评估的私有知识直接提升为全局知识。

## 5. 进化系统规则

1. 进化策略仅允许 REPAIR/OPTIMIZE/INNOVATE/DEFER/ESCALATE。
2. INNOVATE 必须具备验证门禁与回滚策略。
3. 进化失败必须进入统计与熔断评估，不允许静默失败。

## 6. 安全与权限规则

1. 权限检查必须先于路由与工具执行。
2. 高风险工具必须经过 Hook/Sandbox 双重校验。
3. 密钥与凭据禁止入库、禁止硬编码、禁止提交版本库。
4. 所有敏感操作必须写审计日志并保留关联ID。

## 7. 部署运维规则

1. 配置变更必须版本化并可回滚。
2. 生产发布前必须通过健康检查与关键链路回归。
3. 数据备份恢复需定期演练并记录RPO/RTO达成情况。

## 8. 文档与评审规则

1. 架构文档保持“框架级”粒度，不混入临时实现细节。
2. 每次重大变更至少更新：相关框架文档 + 本规则文件影响项。
3. 代码评审需逐项检查：
   - 是否违反权限先行
   - 是否绕过统一模型
   - 是否破坏知识/进化闭环
   - 是否缺少观测与审计

## 9. 变更准入清单（提交前）

- [ ] 功能归属层明确
- [ ] 权限路径完整
- [ ] 日志与指标可观测
- [ ] 失败路径可回滚
- [ ] 相关文档已同步

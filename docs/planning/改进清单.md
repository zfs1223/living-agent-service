# 改进清单：部门固定数字员工状态页视觉升级方案

> 目标：将 `Star-Office-UI-master` 的“数字办公室 / 状态看板”展示风格，迁移到 `frontend` 中各部门的固定数字员工状态页面，重点提升场景感、状态可视化、信息层级与交互体验。
>
> 本文档同时给出 `DepartmentDetail.tsx` 与 `index.css` 的具体拆分与改造建议，作为前端实施依据。
>
> 上次更新：2026-04-25

---

## 1. 背景与目标

### 1.1 现状
当前部门页已经具备基础的管理后台结构：
- 顶部部门信息区
- 部门大脑区
- 数字员工区
- 部门成员区
- 最近动态区

但整体更像“后台详情页”，缺少以下特征：
- 办公场景化表达不足
- 固定数字员工状态不够直观
- 页面层级偏平，记忆点不强
- 动态感较弱，缺少“正在工作”的氛围

### 1.2 目标
将部门页升级为：
- **部门数字员工状态中心**
- **动画化办公室看板**
- **可感知工作状态的工位空间**

让用户一眼看出：
- 这个部门有多少固定数字员工
- 他们现在在做什么
- 谁在工作、谁在休息、谁出现异常
- 部门整体是否健康运行

---

## 2. 核心设计方向

### 2.1 办公室场景化
建议将部门页面抽象为一个“数字办公室”：
- 页面顶部是部门入口与总览
- 中间是办公室主空间
- 下方或侧边是工位区、休息区、协作区、告警区

### 2.2 工位化表达
每个固定数字员工建议不再只是列表卡片，而是：
- 一个有位置归属的工位节点
- 一个能表现状态变化的动画角色
- 一个能展示当前任务的状态气泡

### 2.3 状态可视化
建议将员工状态拆为三个层次：
- **视觉层**：颜色、发光、动画、位置
- **语义层**：工作中 / 空闲 / 休息 / 异常 / 离线
- **信息层**：当前任务、最近活跃时间、职责、协作对象

---

## 3. 功能改进清单

### P0 必做项

#### 3.1 顶部 Hero 区改造
- 用更强的渐变背景替代普通卡片背景
- 显示部门名称、部门定位、部门状态标签
- 增加在线数字员工数、异常数、任务数等 KPI
- Hero 区整体风格向“办公室门牌 + 控制台”靠拢

#### 3.2 数字员工状态墙重构
- 从普通卡片列表升级为“工位墙”
- 每个员工卡展示：
  - 角色/头像
  - 当前状态
  - 当前工位
  - 最近活跃时间
  - 当前任务摘要
- 状态徽标要统一规范：
  - running / busy / idle / error / offline

#### 3.3 部门总览指标补强
- 在线员工数
- 忙碌员工数
- 空闲员工数
- 异常员工数
- 今日任务完成数
- 今日响应时长

#### 3.4 空状态与加载态升级
- 空状态要结合“办公室”语义
- 加载态建议使用骨架屏或轻动效，而不是单行文字
- 异常态需要更明确的提示文案和行动入口

---

### P1 强烈建议项

#### 3.5 办公室动画空间
建议将部门主区域做成一个可动画化的办公室：
- 会议区
- 工位区
- 休息室
- 协作区
- 告警区

员工可以根据状态在不同区域“移动”：
- 工作中 → 在工位区
- 空闲 → 走到休息室或待命区
- 协作中 → 站到协作区
- 异常 → 高亮到告警区

#### 3.6 员工小人动画
建议将固定数字员工表现为“动画小人 / 像素角色”：
- 站在不同工位上
- 走动到任务区
- 空闲时移动到休息室
- 处理任务时出现气泡、光效、手势变化

如果暂时无法上真动画，也可以先做：
- 轻微位移
- 呼吸效果
- 状态点闪烁
- 任务气泡浮动

#### 3.7 最近活动流
增加动态记录区，展示：
- 员工状态变化
- 任务开始 / 完成
- 异常告警
- 协作消息

#### 3.8 筛选与排序
- 按状态筛选
- 按部门角色筛选
- 按最近活跃排序
- 异常优先置顶

---

### P2 体验增强项

#### 3.9 轻量动效体系
- 卡片 hover 微浮起
- 状态点呼吸动画
- 数字缓动
- 工位光效流动
- 角色停留时轻微抖动或呼吸

#### 3.10 响应式改造
- 大屏：显示完整办公室空间与多工位布局
- 中屏：工位墙 + 总览卡
- 小屏：折叠为单列状态列表

#### 3.11 统一设计规范
将该页样式抽象为可复用组件：
- `OfficeHero`
- `OfficeStats`
- `EmployeeStationCard`
- `OfficeFloorMap`
- `ActivityTimeline`
- `StatusBadge`

## 4. `DepartmentDetail.tsx` 前端具体改造方案

### 4.1 当前问题
当前 `DepartmentDetail.tsx` 的主要问题是：
- JSX 太长，职责混杂
- 数据获取、权限判断、页面布局、状态文案全部写在一个文件里
- 样式大量 inline，难以维护
- 数字员工区只有“卡片列表”，缺少场景化表达

### 4.2 建议拆分方式
建议按“数据 / 视图 / 业务能力”拆分。

#### 4.2.1 页面容器层
保留 `DepartmentDetail.tsx` 作为页面入口，只负责：
- 路由参数解析
- 数据获取与聚合
- 权限判断
- 页面状态分发

#### 4.2.2 拆成子组件
建议新增以下组件：
- `DepartmentHero`
- `DepartmentOverviewStats`
- `OfficeScene`
- `EmployeeStationGrid`
- `EmployeeStationCard`
- `DepartmentBrainPanel`
- `DepartmentMemberList`
- `DepartmentActivityFeed`
- `DepartmentTabs`

#### 4.2.3 页面职责重排
`DepartmentDetail.tsx` 中只保留：
- `useQuery` 拉取部门、脑、员工、成员
- `canAccessDepartmentBrain` / `canSeeDeptTasks`
- `handleBrainChat` / `handleAgentClick` / `handleCreateAgent`
- tab 切换逻辑
- 将数据传入上述子组件

---

### 4.3 推荐的数据结构
建议在页面层先整理出统一视图模型，例如：
- `departmentSummary`
- `officeStats`
- `stationEmployees`
- `activityItems`
- `accessFlags`

这样子组件不需要关心底层 API 字段差异。

---

### 4.4 建议的页面结构

1. `DepartmentHero`
2. `DepartmentOverviewStats`
3. `DepartmentTabs`
4. `OfficeScene` 或 `EmployeeStationGrid`
5. `DepartmentBrainPanel`
6. `DepartmentMemberList`
7. `DepartmentActivityFeed`

如果启用动画办公室，可以把第 4 项替换为：
- 左侧工位区
- 中间主办公室
- 右侧协作 / 休息 / 告警区

---

### 4.5 员工状态空间映射建议
建议定义统一映射：
- `ACTIVE` / `running` → 工位区工作
- `IDLE` → 休息室或待命区
- `BUSY` → 协作区 / 任务区
- `ERROR` → 告警区
- `INACTIVE` / `OFFLINE` → 远端暗区或离线区

这样视觉和业务状态是一一对应的。

## 5. `index.css` 前端具体改造方案

### 5.1 当前问题
当前 `index.css` 已经有一套可用设计系统，但部门页相关样式存在：
- 组件样式过于平铺
- 页面专属样式混杂在全局文件中
- `DepartmentDetail` 页面依赖大量 inline style
- 动画办公室所需的视觉状态缺少统一变量

### 5.2 建议拆分方式
建议保留 `index.css` 作为全局基础样式，同时新增页面专属样式文件，例如：
- `src/styles/department-detail.css`
- `src/styles/office-scene.css`
- `src/styles/employee-station.css`

如果当前不方便拆文件，也至少要在 `index.css` 中分区清晰管理。

---

### 5.3 建议新增的样式分区

#### 5.3.1 办公室主场景样式
- 背景渐变
- 网格底纹
- 柔光层
- 透视感空间层级

#### 5.3.2 工位样式
- 工位台面
- 角色站位点
- 状态灯
- 任务气泡
- 运行中发光效果

#### 5.3.3 休息室样式
- 更柔和的背景色
- idle 状态专属视觉
- 休息/待命文案

#### 5.3.4 告警区样式
- 红橙色强调
- 抖动 / 闪烁提示
- 错误态卡片突出显示

#### 5.3.5 角色动画样式
- `moveToDesk`
- `moveToLounge`
- `taskPulse`
- `statusGlow`
- `idleBreath`

---

### 5.4 建议新增的 CSS 变量
建议扩展：
- `--office-bg`
- `--office-panel`
- `--office-glow`
- `--office-station`
- `--office-lounge`
- `--office-alert`
- `--employee-active`
- `--employee-idle`

这样后续做主题和角色切换会更方便。

## 6. 推荐落地顺序

### 第一阶段：结构升级
- 拆分 `DepartmentDetail.tsx`
- 把 inline style 迁移为组件和 CSS 类
- 完成顶部 Hero 和 KPI 区

### 第二阶段：状态墙升级
- 数字员工卡片改造成工位卡
- 统一状态灯与标签
- 增加最近活动流

### 第三阶段：动画办公室
- 引入工位区、休息室、协作区、告警区
- 固定数字员工根据状态移动到不同区域
- 先做轻动效，再逐步加入更完整动画

### 第四阶段：统一风格体系
- 抽象通用组件
- 统一各部门页面风格
- 建立可复用的状态看板设计规范

---

## 7. 风险与约束

### 7.1 风险
- 动画过多会影响性能
- 视觉风格过于花哨会损害信息可读性
- 页面改造范围较大时，容易与现有布局冲突

### 7.2 控制原则
- 先保证信息清晰，再做动画增强
- 动效必须服务于状态表达
- 组件拆分优先于样式堆叠
- 逐步替换，不建议一次性大改全部页面

---

## 8. 一句话结论

可以把 `Star-Office-UI-master` 的展示风格迁移到 `frontend` 的部门固定数字员工状态页，而且最合适的方向不是“普通美化”，而是把页面升级成一个**会动的数字办公室状态中心**：

- 固定数字员工像工位上的小人一样工作
- 空闲时走向休息室
- 异常时进入告警区
- 页面本身成为一个可感知的“部门运行空间”

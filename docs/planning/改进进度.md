# 改进进度：数字办公室状态系统

> 更新日期：2026-04-25
>
> 当前目标：将部门详情页从“像素办公室原型”推进为“可运行的动态办公室状态系统”，并为后端事件流、实时状态、空间调度保留稳定接口。

---

## 1. 已完成进度

### 1.1 页面结构拆分
- `DepartmentDetail.tsx` 已拆为页面容器 + 子组件组合。
- 已拆出多个独立组件文件，用于承载不同职责。

### 1.2 办公室空间原型
- 已完成办公室主空间雏形。
- 包括工位区、协作区、休息室、告警区、离线区等概念。
- 视觉上已经具备“数字办公室”语义。

### 1.3 状态驱动基础
- 已加入状态到区域的映射。
- 已加入基础 motion profile。
- 已加入过渡阶段、方向、进度等运动语义。
- 已加入更自然的前排 / 后排 / 角落 / 过道工位布局。

### 1.4 时间轴与事件流
- 已引入时间轴组件。
- 已支持由前端推导出状态事件。
- 已为后端事件流接入预留位置。
- 已加入时间轴自动滚动与实时流优化。

### 1.5 后端适配层
- 已新增后端事件输入适配层。
- 已新增 `emitEvent` / `ingestEvents` 接口。
- 已与 `living-agent-service` 的 API 约定对齐，具备继续接入 `/api/office/*` 与 `/api/departments/*` 的基础。

---

## 2. 当前进行中的改造

### 2.1 后端事件流接入层
正在补充：
- 支持事件输入
- 支持事件缓冲
- 支持事件分类
- 支持由后端驱动 timeline
- 支持从 `/api/office/department/{department}` 等接口持续获取部门态势

### 2.2 空间座位与工位编排层
正在补充：
- 前排 / 后排 / 走道 / 角落位
- 更像真实办公室的工位分布
- 进入、停靠、回位时的视觉差异

### 2.3 状态调度稳定性
正在补充：
- 冷却时间更精细化
- 任务完成后回位逻辑强化
- 告警优先级与冲突处理
- 避免频繁抖动与闪烁

### 2.4 API 联调
正在补充：
- 事件源从 API 适配到前端状态流
- 后端 Office / Department API 的事件字段映射
- 需要确认部门态势接口返回结构后做最终归并

---

## 3. 下一步计划

1. 接通后端事件输入与前端 timeline。
2. 为 `OfficeZonePanel` 增加更像办公室座位编排的布局。
3. 强化 `useOfficePresence` 的事件归并与稳定逻辑。
4. 保留原有部门页功能不缺失。

---

## 4. 验收标准

- 原有部门页功能完整保留。
- 数字员工能按状态显示在不同区域。
- 状态变化不会高频闪烁。
- 时间轴能接收并展示事件。
- 后端事件流接入后无需推翻前端结构。

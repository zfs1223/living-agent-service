# Living Agent Service 权限与入口矩阵

> 目标：把"登录状态、身份、页面、按钮、通道、语音、流程、审计"统一成一套可执行规则，作为前后端与产品的共同基线。
>
> **文档状态**: 2026-07-09 更新 — 修正行号引用、补充部门对话入口分层、更新代码实现状态、补充桌面端

## 1. 基本原则

1. **登录状态先于身份，身份先于页面，页面先于通道，通道先于流程**
   - 先判断是否登录，未登录只能闲聊
   - 登录后先判定身份，再决定可见页面
   - 再根据页面决定可见按钮/入口
   - 再根据入口决定 WebSocket/HTTP 通道
   - 最后再决定流程是自动还是半自动

2. **登录前统一闲聊，登录后统一部门大脑**
   - 未登录：任何人只能跟闲聊神经元对话，不区分身份
   - 登录后：所有人统一通过部门大脑对话，不再暴露闲聊入口

3. **固定员工不直接面向个人聊天**
   - 固定数字员工不开放单体直连聊天
   - 对固定员工的指挥、协作、任务分派统一收口到部门大脑、项目互动群、部门协调群

4. **部门大脑是组织级入口，不是普通助手**
   - 所有部门默认都有部门大脑
   - 部门大脑负责本部门事务处理、内部协调、跨部门协调发起

5. **语音/文字由前端开关控制**
   - 未登录：不可使用语音
   - 已登录：根据前端对话页面的"语音开关"决定是否启用 ASR/TTS
   - ⚠️ 当前前端语音开关尚未实现（后端链路已就绪）

6. **流程只能是标准规范流程**
   - 只保留 `自动` 和 `半自动` 两级
   - 不保留"建议级"作为正式流程结果

## 1.6 固定数字员工禁止直连规则

**核心规则：任何人不能直接跟"固定数字员工"沟通，但可以跟个人新建的数字助理沟通。**

1. **固定数字员工 (origin=fixed)**：
   - 企业正式岗位的数字化员工（如"代码审查员"、"会计"、"客服代表"等）
   - **禁止任何人通过 `/ws/agent` 直连聊天**
   - 只能通过部门大脑、项目互动群、部门协调群协作
   - 后端在 `AgentWebSocketHandler` 连接建立时强制拦截 ✅ 已实现
   - 前端 `Chat.tsx:L136,L196` 检测到 `origin=fixed` 时自动降级到 `/ws/public` ✅ 已实现
   - 前端 `AgentDetail.tsx:L187-L194` 检测到 `origin=fixed` 时隐藏 chat tab ✅ 已实现
   - 前端判定字段：`agent.origin`（小写），非 `employee_origin`

2. **个人数字助理 (origin=personal)**：
   - 用户个人创建的数字助理，属于个人轨
   - **允许通过 `/ws/agent` 直连聊天**
   - 保留 `id` 直连入口
   - 不进入企业正式流程

3. **人类员工 (origin=human)**：
   - 代表真实人类员工
   - 允许通过 `/ws/agent` 直连聊天（如果开放此功能）

4. **入口矩阵更新**：
   - `origin=fixed` → 禁止 `/ws/agent`，前端自动降级到 `/ws/public`，只能走部门大脑通道
   - `origin=personal` → 允许 `/ws/agent`，保留直连入口
   - `origin=human` → 允许 `/ws/agent`，保留直连入口（如开放）

## 1.5 语音对话入口设计

**语音功能由两部分协同工作：Rust 原生音频编解码（Opus）+ Python Daemon 的 ASR/TTS，受前端对话页面开关控制：**

1. **语音处理完整链路**（`AgentService.processAudioFullChain()`）：
   ```
   前端录音 → Opus 编码 → Base64
       │
       ▼
   WebSocket "audio_full" 消息 → AgentWebSocketHandler
       │
       ▼
   AgentService.processAudioFullChain()
       │
       ├─ Base64 解码
       ├─ AudioNative.Processor.decodeOpus()  ← Rust JNI (opus_codec.rs)
       ├─ savePcmToWav()
       ├─ modelManager.recognizeSpeech()       ← Sherpa-ONNX ASR → 文本
       ├─ modelManager.processChatWithIntent()  ← 意图分类 + LLM 处理 → 响应文本
       ├─ modelManager.synthesizeSpeechRaw()   ← MeloTTS → PCM
       ├─ AudioNative.Processor.encodePcm()    ← Rust JNI (opus_codec.rs)
       └─ Base64 编码 → WebSocket 返回 → 前端播放
   ```

2. **Rust 原生 Opus 编解码**：
   - 实现文件：`living-agent-native/src/audio/opus_codec.rs`
   - JNI 绑定：`living-agent-native/src/jni/audio_jni.rs`
   - Java 调用：`AudioNative.Processor` 类
   - 编码参数：16kHz 采样率、单声道、960 帧大小

3. **ASR/TTS 模型**：
   | 能力 | 模型 | 调用方式 |
   |------|------|---------|
   | ASR 语音识别 | Sherpa-ONNX | `modelManager.recognizeSpeech()` |
   | TTS 语音合成 | MeloTTS / Supertonic | `modelManager.synthesizeSpeechRaw()` |

4. **意图分类与路由**：
   - `modelManager.processChatWithIntent()` 负责意图分类和 LLM 处理
   - ASR/TTS 由 `modelManager` 通过 NamedPipe 调用 Python Daemon 提供
   - ChatNeuron (Qwen3-0.6B) 是**闲聊神经元**，**不提供 ASR/TTS 能力**
   - ChatNeuron 负责闲聊响应、简单问答，经 ChatNeuronRouter 路由（仅文字闲聊场景）

5. **权限与语音的关系**：
   - **未登录：不可使用语音**（无认证无法调用 ASR/TTS）
   - 已登录：根据前端对话页面的"语音开关"决定是否启用
   - 语音对话的权限与文字对话一致（董事长可跨部门，其他仅限本部门）
   - 语音/文字模式对后端处理链路一致：语音经 ASR 转文本后，与文字输入走完全相同的 `modelManager.processChatWithIntent()` 路由

## 2. 技术判定字段

### 2.1 固定员工判定

- **后端统一使用字段**：`employee_origin`
- **前端实际使用字段**：`agent.origin`（小写，值如 `'fixed'`、`'personal'`、`'human'`）
- **用途**：
  - 区分固定数字员工、个人助手、外部接入对象
  - 驱动权限判断、入口显示、审计归类、流程路由

### 2.2 岗位判定

- 岗位由组织岗位体系维护
- ⚠️ 当前前端岗位判定使用 `user?.title?.includes('负责人')` 文本匹配（`DepartmentDetail.tsx:L57`），与"不依赖 title 文本匹配"规则存在偏差
- 岗位变更后立即生效

### 2.3 部门判定

- 部门是页面与协调的基础维度
- 部门大脑按部门默认存在
- 跨部门协调通过部门大脑之间的协调链路完成

## 3. 权限与入口矩阵（登录状态 × 身份 × 页面 × 按钮 × 通道）

> 通道遵循"登录状态优先，身份兜底"。

### 3.1 登录前

| 登录状态 | 身份 | 主要页面 | 可见对话按钮/入口 | 允许通道 | 语音 | 说明 |
|---------|------|---------|------------------|---------|------|------|
| 未登录 | 任何人 | `/chat`（无参数） | 闲聊输入框 | `/ws/public` | 不可用 | 统一闲聊，不区分身份 |

### 3.2 登录后

| 身份 | 主要页面 | 可见对话按钮/入口 | 允许通道 | 语音 | 说明 |
|------|---------|------------------|---------|------|------|
| 董事长/FULL | 部门列表页 | **所有部门**"对话"按钮 | `/ws/dept/{brain}` | 可用 | 可访问**所有**部门大脑 |
| 董事长/FULL | 部门页 `/departments/:code` | 部门大脑"对话"按钮 | `/ws/dept/{brain}` | 可用 | 固定部门大脑入口 |
| 董事长/FULL | 通用聊天页 `/chat`（无参数） | 默认聊天输入框 | `/ws/enterprise` | 可用 | 董事长频道 |
| 董事长/FULL | 数字员工详情 `/agents/:id#chat` | 聊天 tab（仅个人助手） | `/ws/agent` | 可用 | 固定员工直连禁用 |
| 部门负责人 | 本部门页 `/departments/:code` | 本部门"对话"按钮 | `/ws/dept/{brain}` | 可用 | 仅限本部门 |
| 部门负责人 | 通用聊天页 `/chat`（无参数） | 默认聊天输入框 | `/ws/dept/{department_id}` | 可用 | 本部门频道 |
| 部门负责人 | 数字员工详情 `/agents/:id#chat` | 聊天 tab（仅个人助手） | `/ws/agent` | 可用 | 固定员工直连禁用 |
| 普通员工 | 本部门页 `/departments/:code` | 本部门"对话"按钮 | `/ws/dept/{brain}` | 可用 | 仅限本部门 |
| 普通员工 | 通用聊天页 `/chat`（无参数） | 默认聊天输入框 | `/ws/dept/{department_id}` | 可用 | 本部门频道 |
| 普通员工 | 个人助理详情 `/agents/:id#chat` | 聊天 tab（仅个人助手） | `/ws/agent` | 可用 | 仅自己创建的个人助手 |
| 普通员工 | 项目互动群 | 项目内沟通消息 | 群聊通道 | 可用 | 项目成员内部沟通 |
| 访客/低权限 | `/chat`（无参数） | 默认聊天输入框 | `/ws/public` | 不可用 | 公共通道 |

### 3.3 固定员工专门约束

| 对象类型 | 直连聊天入口 | 管理入口 | 协作入口 | 可见性要求 |
|---------|------------|---------|---------|-----------|
| 固定数字员工 | 禁用（前端自动降级到 `/ws/public`） | 部门大脑 | 项目互动群/协调群 | 管理可见、可审计 |
| 个人助手 | 允许 | 个人或部门页面 | 可选 | 受个人权限边界控制 |

### 3.4 流程生效等级矩阵

| 流程类型 | 生效等级 | 是否需要人类参与 | 说明 |
|---------|---------|----------------|------|
| 标准自动流程 | 自动 | 否 | 满足规则即生效 |
| 标准半自动流程 | 半自动 | 是 | 系统执行前/后需人类确认 |
| 其他非标准流程 | 不建议 | 视情况 | 应尽量收敛为标准流程 |

## 4. 页面到入口的固定映射

### 4.1 登录前：通用聊天页 `Chat.tsx`

| 属性 | 值 |
|------|------|
| 路由 | `/chat`（无参数） |
| WebSocket 通道 | `/ws/public` |
| 处理能力 | 闲聊神经元 (Qwen3Neuron) |
| 语音 | 不可用 |

### 4.2 登录后：部门详情页 `DepartmentDetail.tsx`

- 路由：`/departments/:code`
- **两个对话入口，面向不同用户**：
  - **DepartmentBrainPanel**（"对话"按钮）→ 跳转 `/chat?brain={code}&dept={departmentName}`
    - 权限：`canAccessDepartmentBrain = Boolean(isEnterprise || isDepartmentHead)`（`DepartmentDetail.tsx:L58`）
    - 董事长/FULL：可访问所有部门 ✅
    - 部门负责人：可访问本部门 ✅
    - 普通员工：按钮不可见 ❌（需通过通用聊天页 `/chat` 走 `/ws/dept/{department_code}`）
  - **DepartmentChatInline**（内嵌快捷聊天）→ 直连 `/ws/dept/{code}`
    - 权限：`canAccessDepartmentBrain = isEnterprise`（`DepartmentChatInline.tsx:L70`）
    - 仅董事长/FULL 可用（管理级快捷入口）
    - 部门负责人和普通员工不显示此组件
- **所有部门人类员工的实际对话入口**：部门页"对话"按钮（DepartmentBrainPanel）或通用聊天页 `/chat` → `/ws/dept/{department_code}`
- 约束：
  - 固定员工不直接出现在这里的单体聊天按钮中
  - **董事长**：可进入任意部门对话
  - **其他用户**：仅可进入本部门对话

### 4.3 登录后：通用聊天页 `Chat.tsx`

- 路由：
  - `/chat?id=xxx`
  - `/chat?brain=dept&dept=name`
  - `/chat`
  - `/agents/:id/chat`
- 通道选择（`Chat.tsx:L190-L211`）：
  1. 未登录 → `/ws/public`（闲聊）
  2. `id` 存在 → 检查 `origin`（`Chat.tsx:L136` 判定 `isFixedEmployee`）：
     - `origin=fixed` → 降级到 `/ws/public`
     - `origin=personal` → `/ws/agent`
  3. `brain` 存在 → `/ws/dept/{brain}`（权限校验在后端）
  4. 否则 `/chat` 按身份兜底：
     - 董事长/FULL → `/ws/enterprise`（`wsApi.chairmanUrl()`）
     - 有部门 → `/ws/dept/{department_code}`
     - 无部门 → `/ws/public`

### 4.4 登录后：数字员工详情页 `AgentDetail.tsx`

- 路由：`/agents/:id#chat`
- 仅允许个人助手或可管理的非固定对象进入单体聊天
- 对固定员工：只保留展示、配置、协作，不保留直接聊天入口（隐藏 chat tab）
- 代码实现（`AgentDetail.tsx:L187-L199`）：
  - `origin = String((agent as any)?.origin || '').toLowerCase()`
  - `isFixedEmployee = origin === 'fixed'`
  - `canOpenChat = isHumanEmployee && !isFixedEmployee && !isOpenClaw`
  - `canShowChatTab = canOpenChat`
  - chat tab 通过 `visibleTabs` 过滤隐藏

### 4.5 桌面端对话入口

> ⚠️ 桌面端（`living-agent-desktop/`）的对话入口与前端不完全一致，当前存在以下差异：

| 桌面端入口 | WebSocket 通道 | 权限控制 | 说明 |
|-----------|---------------|---------|------|
| `OfficeChatPage.tsx` | `/ws/dept/{deptCode}` | 无前端权限过滤 | 自建 WebSocket，绕过 `ws-client.ts` |
| `ws-client.ts`（默认） | `/ws/agent` | 无 origin 校验 | 主进程 WebSocket 客户端 |
| 闲聊入口 | ❌ 不存在 | — | 桌面端无 `/ws/public` 支持 |
| 董事长频道 | ❌ 不存在 | — | 桌面端无 `/ws/enterprise` 支持 |

- **已知问题**：
  - `OfficeChatPage.tsx:L322,L328` 自建 WebSocket 连接 `/ws/dept/{dept}`，绕过了 `ws-client.ts` 的重连/心跳机制

  - 固定员工直连防护仅依赖后端拦截，桌面端前端无 `origin` 校验

## 5. 后端实现边界

### 5.1 WebSocket 注册

| 通道 | 处理器 | 说明 |
|------|--------|------|
| `/ws/agent` | `AgentWebSocketHandler` | 数字员工/个人助理对话 |
| `/ws/dept/*` | `DepartmentWebSocketHandler` | 部门大脑对话 |
| `/ws/enterprise` | `DepartmentWebSocketHandler` | 董事长频道 |
| `/ws/public` | `DepartmentWebSocketHandler` | 公共闲聊通道 |

### 5.2 固定员工直连拦截

- 后端根据 `employee_origin` 判断是否为固定员工
- 若为固定员工，且请求试图走单体聊天入口，则拒绝连接
- 前端 `Chat.tsx:L136,L196` 检测到 `origin=fixed` 时自动降级到 `/ws/public` ✅
- 前端 `AgentDetail.tsx:L187-L194` 检测到 `origin=fixed` 时隐藏 chat tab ✅
- 桌面端前端无 origin 校验，仅依赖后端拦截 ⚠️
- 正确入口应为部门大脑、项目互动群、部门协调群

### 5.3 部门大脑权限

- 每个部门默认有部门大脑
- **董事长/FULL**：可访问所有部门大脑
- **其他已登录用户**：仅可访问本部门大脑
- 本部门问题优先由本部门大脑处理
- 跨部门协调必须通过部门大脑之间的协调链路
- 不允许直接越过对方部门大脑调度固定员工

### 5.4 语音处理

| 组件 | 说明 |
|------|------|
| 音频编解码 | Rust 原生 Opus（`opus_codec.rs`），通过 JNI 供 Java 调用 |
| ASR | Sherpa-ONNX，通过 `modelManager.recognizeSpeech()` 调用 |
| 意图分类 | `modelManager.processChatWithIntent()`，负责意图分类和 LLM 处理 |
| TTS | MeloTTS / Supertonic，通过 `modelManager.synthesizeSpeechRaw()` 调用 |
| 音频传输 | Base64 编码，通过 WebSocket 文本消息传输 |
| 权限控制 | 未登录不可使用，已登录由前端开关控制 |

### 5.5 项目互动群

- 项目互动群属于项目成员内部群聊
- 群可自动生成、可保留、可自动归档
- 群内行为默认进入管理可见范围

## 6. 流程规范

### 6.1 组合维度

流程、权限、入口按以下组合维度配置：

- 部门
- 岗位
- 项目

### 6.2 自动 / 半自动

1. **自动**
   - 无人类参与
   - 仅在规则满足后直接生效

2. **半自动**
   - 允许人类参与确认
   - 可在执行前确认，也可在执行后复核，按流程定义固定

### 6.3 无人类员工项目

- 如果项目中没有人类员工，则只能走自动流程
- 不允许配置半自动人工确认节点

## 7. 组织配置与生效

### 7.1 岗位绑定变更

- 变更后立即生效
- 需要同步影响：
  - 页面可见性
  - 入口可见性
  - 权限判断
  - 协调关系图
  - 在线会话权限

### 7.2 维护权

- 董事长拥有最高配置权
- 董事长可直接维护岗位、权限、部门协调关系
- 董事长可授权人类 HR 维护
- 不需要二级审批

### 7.3 登录与岗位绑定

- 手机号登录后，基于岗位绑定决定初始可见页面与入口
- 若岗位中途变化，通过系统指令或会话刷新立即收敛权限

## 9. 实施口径摘要

1. **登录前统一闲聊**：未登录只能走 `/ws/public`，不可使用语音
2. **登录后统一部门大脑**：所有人通过部门大脑对话，不暴露闲聊入口
3. 固定员工按 `employee_origin` 判定，不允许直连聊天，前端自动降级
4. **董事长可访问所有部门大脑**，其他仅限本部门
5. 部门大脑默认存在
6. 跨部门协调走部门大脑之间的协调链路，不直调固定员工
7. 项目互动群可自动生成、可保留、可自动归档
8. 语音/文字由前端对话页面开关控制
9. 流程只保留自动/半自动
10. 岗位绑定变更立即生效
11. 董事长可直接维护岗位、权限、协调关系，无需二级审批

## 10. 外部服务管理员与自动激活

### 10.1 管理员账号体系

主脑（MainBrain）持有所有外部服务的**管理员账号**，负责初始化配置、为员工分配账号、权限回收与审计。管理员账号**仅主脑使用**，不分配给数字员工：

| 服务 | 管理员 | 密码 | 端口 | 用途 |
|------|--------|------|------|------|
| OpenProject | `admin` | `admin123456` | 8386 | 主脑管理项目、分配员工账号 |
| GitLab | `root` | (初始配置) | 8385 | 主脑管理仓库、分配员工账号 |
| Jenkins | `admin` | (初始配置) | 8384 | 主脑管理CI/CD、分配员工账号 |
| Memos | 首个注册用户 | - | 8383 | 主脑管理知识备忘 |

### 10.2 主脑账号分配规则

主脑根据岗位和业务需要，为固定数字员工在外部服务中注册**专属账号**，按需分配：

| 外部服务 | 需要账号的岗位 | 不需要账号的岗位 | 分配权限 |
|---------|--------------|----------------|---------|
| OpenProject | 所有部门（项目管理、任务跟踪） | 无 | Developer/Reporter（按岗位） |
| GitLab | 研发部（代码编辑、代码审查） | 财务部、法务部、客服部 | Developer/Reporter |
| Jenkins | 研发部（CI/CD 构建） | 其他部门 | Builder/Viewer |
| Memos | 所有部门（知识记录） | 无 | Editor/Viewer |

### 10.3 固定数字员工账号分配

主脑在初始化固定数字员工时，根据其岗位自动在相关外部服务中注册账号：

| 员工 | OpenProject | GitLab | Jenkins | Memos |
|------|------------|--------|---------|-------|
| 代码审查员 | ✅ `{id}-bot` (Developer) | ✅ `{id}-bot` (Developer) | ✅ `{id}-bot` (Builder) | ✅ `{id}-bot` (Editor) |
| 会计 | ✅ `{id}-bot` (Reporter) | - | - | ✅ `{id}-bot` (Editor) |
| 客服代表 | ✅ `{id}-bot` (Reporter) | - | - | ✅ `{id}-bot` (Editor) |
| 法务专员 | ✅ `{id}-bot` (Reporter) | - | - | ✅ `{id}-bot` (Editor) |

> 命名规则：`{employeeId}-bot`，例如 `code-reviewer-bot`、`accountant-bot`

### 10.4 临时数字员工账号

临时数字员工在任务执行时由主脑按需创建，仅授予任务所需的最小权限，任务完成后回收：

| 类型 | 创建时机 | 命名规则 | 权限范围 | 生命周期 |
|------|---------|---------|---------|---------|
| 临时数字员工 | 任务执行时 | `temp-{taskId}-{random}` | 仅任务相关资源 | 任务完成后回收 |

### 10.5 董事长自动获得管理员

当用户注册为"董事长"身份后，系统自动赋予以下管理员权限：

| 服务 | 管理员赋予方式 | 说明 |
|------|--------------|------|
| Living Agent Service | `AccessLevel.FULL` + `admin=true` | 系统内部最高权限 |
| OpenProject | 自动设为 `admin=true` | 项目管理管理员 |
| GitLab | 自动加入 `admin` 组 | 代码仓库管理员 |
| Jenkins | 自动加入 `admin` 角色 | CI/CD 管理员 |

### 10.6 自注册与自动激活

为方便主脑批量创建账号，所有外部服务的自注册均设置为自动激活：

| 服务 | 自注册设置 | 说明 |
|------|-----------|------|
| OpenProject | `self_registration=3` (自动激活) | 注册后无需管理员审批 |
| GitLab | `signup_enabled=true` | 注册后自动激活 |
| Jenkins | 安全矩阵配置 | 按需开放 |
| Memos | 默认开放注册 | 首个用户为管理员 |

# Living Agent Service 对话入口逻辑梳理

> 目的：把"什么岗位有什么页面、对应什么对话入口"一次讲清楚，便于产品、前端、后端统一理解。
> 
> **文档状态**: 2026-04-29 重大更新 — 统一登录前后的对话入口规则
> 
> **核对范围**: Chat.tsx, AgentDetail.tsx, DepartmentDetail.tsx, AgentWebSocketHandler, DepartmentWebSocketHandler

## 0. 核心原则：登录前与登录后

系统对话入口按**登录状态**分为两层：

### 0.1 登录前：统一只走闲聊

| 规则 | 说明 |
|------|------|
| 唯一可用 | 闲聊神经元 (Qwen3Neuron) |
| WebSocket 通道 | `/ws/public` |
| 可用能力 | 闲聊、简单问答 |
| 语音 | 不可用（无认证无法调用 ASR/TTS） |
| 文字 | 可正常使用 |
| 后端处理 | 不经过 ChatNeuronRouter，直接走 Python Daemon 闲聊路径 |

**一句话：登录前任何人只能跟闲聊神经元对话，不区分身份、部门、权限。**

### 0.2 登录后：统一进入"部门大脑"

| 规则 | 说明 |
|------|------|
| 唯一入口 | 部门大脑对话 |
| WebSocket 通道 | `/ws/dept/{department_code}` 或 `/ws/enterprise`（董事长） |
| 董事长/FULL | 可对话**所有**部门大脑 |
| 其他已登录用户 | 仅可对话**本部门**的大脑 |
| 语音 | 受前端对话页"语音开关"控制，开启后调用 Python Daemon 的 ASR/TTS |
| 文字 | 默认模式 |

**一句话：登录后不再有"闲聊"入口，统一通过部门大脑对话；董事长可跨部门，其他仅限本部门。**

### 0.3 语音 vs 文字

| 维度 | 文字模式 | 语音模式 |
|------|---------|---------|
| 前端控制 | 默认开启 | 对话页开关控制（默认关闭） |
| 输入 | 键盘输入文本 | 麦克风录音 → Opus 编码 → Base64 传输 → 服务端解码 |
| 输出 | 直接显示文本 | TTS 合成 → Opus 编码 → Base64 传输 → 前端播放 |
| Java 侧音频处理 | 无 | Rust JNI Opus 编解码 → WAV → Sherpa ASR → MeloTTS → PCM → Rust JNI Opus 编码 |
| Python Daemon 音频处理 | 无 | `service="asr"` → Sherpa-ONNX ASR；`service="tts"` → MeloTTS / Supertonic |
| Python Daemon 服务 | 仅需 `service="chat"` | 需要 `asr` + `chat` + `tts` |
| 认证要求 | 需要登录 | 需要登录 + 前端开启语音 |
| 编解码 | 不适用 | Opus（Rust 原生 `opus_codec.rs`），通过 JNI 绑定供 Java 调用 |

## 0.4 前端对话页统一规则

无论用户是董事长、部门负责人还是普通员工，登录后的对话页面统一为：

1. **部门页 `DepartmentDetail.tsx`** → 点击"对话"按钮 → 进入部门大脑对话
2. **对话页面 `Chat.tsx`** → 统一部门大脑对话界面
3. **语音开关** → 对话页右上角开关，控制 ASR/TTS 是否启用

**董事长特殊处理**：董事长可在部门列表中任意选择部门进入对话，不受部门限制。

## 0.5 固定数字员工禁止直连规则

**核心规则：任何人不能直接跟"固定数字员工"沟通，但可以跟个人新建的数字助理沟通。**

1. **固定数字员工 (origin=fixed)**：
   - 代表企业的正式岗位数字员工，如"代码审查员"、"会计"、"客服代表"等
   - **禁止任何人通过 `/ws/agent` 直连聊天**
   - 只能通过部门大脑、项目互动群、部门协调群进行协作
   - 后端 `AgentWebSocketHandler` 在连接建立阶段强制拦截 ✅ 已实现
   - 前端 `AgentDetail.tsx` 隐藏 chat tab ✅ 已实现

2. **个人数字助理 (origin=personal)**：
   - 用户个人创建的数字助理，属于个人轨
   - **允许通过 `/ws/agent` 直连聊天**
   - 保留 `id` 直连入口
   - 不进入企业正式流程

3. **人类员工 (origin=human)**：
   - 代表真实人类员工
   - 允许通过 `/ws/agent` 直连聊天（如果开放了此功能）

4. **前端处理**：
   - `Chat.tsx`：当 agent.origin === 'fixed' 时，自动降级到 `/ws/public` 通道 ✅ 已实现
   - `AgentDetail.tsx`：当 agent.origin === 'fixed' 时，隐藏 chat tab ✅ 已实现

## 0.6 语音对话入口设计

**语音功能由两部分协同工作：Rust 原生音频编解码（Opus）+ Python Daemon 的 ASR/TTS，受前端对话页面开关控制：**

1. **前端语音开关**：
   - 位置：对话页右上角（或底部工具栏）
   - 状态：默认关闭，用户手动开启
   - 开启后：输入框变为麦克风按钮，支持语音输入
   - 关闭时：纯文本输入

2. **前端音频传输**：
   - 前端录音 → Opus 编码 → Base64 字符串 → 通过 WebSocket 文本消息发送
   - 响应接收：服务端返回 Base64 编码的 Opus 音频 → 前端 Opus 解码 → 播放

3. **Java 服务端音频处理链路（核心）**：
   ```
   WebSocket 收到 Base64 Opus
       │
       ▼
   AudioNative.Processor.decodeOpus()  → Rust JNI 调用 opus_codec.rs 解码为 PCM
       │
       ▼
   savePcmToWav()  → 保存为临时 WAV 文件
       │
       ▼
   modelManager.recognizeSpeech()  → Sherpa-ONNX ASR 识别为文本
       │
       ▼
   modelManager.processChatWithIntent()  → 意图分类 + LLM 处理（绕过 ChatNeuronRouter）
       │
       ▼
   modelManager.synthesizeSpeechRaw()  → MeloTTS 生成 PCM 音频
       │
       ▼
   AudioNative.Processor.encodePcm()  → Rust JNI 调用 opus_codec.rs 编码为 Opus
       │
       ▼
   Base64 编码 → 通过 WebSocket 返回前端
   ```

4. **Rust 原生 Opus 编解码**：
   - 实现文件：`living-agent-native/src/audio/opus_codec.rs`
   - 编解码器：Rust `opus` crate（原生 Opus 编解码）
   - JNI 绑定：`living-agent-native/src/jni/audio_jni.rs`
   - Java 调用：`AudioNative.Processor` 类，通过 JNI 调用 Rust 实现
   - 编码参数：16kHz 采样率、单声道、960 帧大小
   - 默认配置：48kHz 采样率、单声道、20ms 帧、24kbps 码率

5. **Python Daemon 语音能力（备用/直连模式）**：
   | 能力 | service 值 | 说明 |
   |------|-----------|------|
   | ASR 语音识别 | `asr` | Sherpa-ONNX 模型，接收 PCM 数据 |
   | TTS 语音合成 | `tts` | MeloTTS / Supertonic，输出 PCM 数据 |
   | 闲聊响应 | `chat` | 带 DualModelIntentClassifier 自动路由 |

   > **注意**：当前 Java 服务端 ASR/TTS 主要走 `ModelManager`（通过 NamedPipe 调用 Python Daemon 的 `recognizeSpeech` 和 `synthesizeSpeech` 方法），
   > 而 `model_daemon.py` 中的 `asr`/`tts` service 也可被直接调用。

6. **语音权限**：
   - 未登录：不可使用语音（无法调用 Python Daemon）
   - 已登录：根据前端开关决定是否启用语音
   - 语音对话的权限与文字对话一致（董事长可跨部门，其他仅限本部门）

### 1.1 登录前入口

| 入口 | WebSocket 通道 | 处理能力 | 说明 |
|------|---------------|---------|------|
| 通用聊天页 `/chat`（无参数） | `/ws/public` | 闲聊神经元 | 登录前唯一可用入口 |

### 1.2 登录后入口

| 入口 | WebSocket 通道 | 处理能力 | 说明 |
|------|---------------|---------|------|
| 部门页 → "对话"按钮 | `/ws/dept/{department_code}` | 部门大脑 | 所有已登录用户 |

| 数字员工详情页 `/agents/:id#chat` | `/ws/agent` | 仅个人助理 | 固定员工不可直连 |

## 1.5 身份与对话入口（前端分层）

系统当前是"**登录状态区分入口，登录后按权限选择部门**"的结构：

### 1.5.1 登录前

- 统一进入闲聊模式
- 只走 `/ws/public` 通道
- 只能与闲聊神经元 (Qwen3Neuron) 对话
- 无语音能力
- 不区分身份、部门、权限

### 1.5.2 登录后 — 董事长 (FULL)

- **可访问所有部门的大脑**
- 可在部门列表中任意选择部门进入对话
- 部门页 `/departments/:code` → 点击"对话" → `/ws/dept/{code}`
- 默认聊天页 `/chat`（无参数）→ 董事长频道 `/ws/enterprise`
- 可查看任意数字员工详情页，但固定员工不显示 chat tab
- 可使用语音功能（前端开关控制）

### 1.5.3 登录后 — 部门负责人

- **只能访问本部门的大脑**
- 本部门页 `/departments/:code` → 点击"对话" → `/ws/dept/{code}`
- 默认聊天页 `/chat`（无参数）→ 本部门频道 `/ws/dept/{department_code}`
- 可查看本部门相关数字员工详情页，但固定员工不显示 chat tab
- 可使用语音功能（前端开关控制）

### 1.5.4 登录后 — 普通内部员工

- **只能访问本部门的大脑**
- 部门页 `/departments/:code` → 点击"对话" → `/ws/dept/{code}`
- 默认聊天页 `/chat`（无参数）→ 本部门频道 `/ws/dept/{department_code}`
- **不可查看固定数字员工详情页**
- **可与自己创建的个人数字助理对话**
- 可使用语音功能（前端开关控制）

### 1.5.5 登录后 — 访客/低权限

- 无部门或权限极低
- 默认走公共频道 `/ws/public`
- 功能受限

**核心原则**：
- 登录前：统一闲聊，不区分身份
- 登录后：统一部门大脑，按权限决定可访问哪些部门
- 所有人都不允许直接跟"固定数字员工"对话

因此对话链路应理解为：

**登录状态 -> 身份/权限 -> 前端页面 -> 对话入口 (部门大脑/个人助理) -> WebSocket 通道 -> 语音/文字模式。**

## 4. 后端对话入口与权限控制

### 4.1 WebSocket 注册入口

| 通道 | 处理器 | 说明 |
|------|--------|------|
| `/ws/agent` | `AgentWebSocketHandler` | 数字员工/个人助理对话 |
| `/ws/dept/{code}` | `DepartmentWebSocketHandler` | 部门大脑对话 |
| `/ws/enterprise` | `DepartmentWebSocketHandler` | 董事长频道 |
| `/ws/public` | `DepartmentWebSocketHandler` | 公共闲聊通道 |

### 4.2 登录前：`/ws/public` 公共通道

- 不需要 token 即可连接
- 后端直接路由到 Qwen3Neuron
- 不经过 ChatNeuronRouter
- 不经过部门大脑
- 仅提供闲聊能力
- **不处理语音**

### 4.3 登录后：`DepartmentWebSocketHandler`（部门/董事长）

- 根据 URI 识别频道：`dept/{code}`、`enterprise`
- 必须鉴权（带有效 token）
- 权限校验：
  - `enterprise`：FULL 或 founder
  - 普通部门：FULL/founder 或部门匹配且权限非 CHAT_ONLY
- 消息主流程：`processWithBrain → agentService.processTextAsync(...)`
- 语音处理：前端控制 ASR/TTS，后端处理与文字相同

### 4.4 `AgentWebSocketHandler`（个人助理）

- 必须带有效 token
- 固定员工拦截：禁止直连
- 个人助理允许直连
- 建连后 `agentService.startSession(sessionId, accessLevel, department)`

## 5. 后端对话处理流程

### 5.1 登录前：闲聊路径

```
用户输入（文字）
    │
    ▼
/ws/public
    │
    ▼
DepartmentWebSocketHandler.handleTextMessage()
    │
    ▼
直接路由到 Qwen3Neuron（不经过 ChatNeuronRouter）
    │
    ▼
ModelManager.processChatWithIntent()
    │
    ▼
Python Daemon: service="chat"
    │
    ▼
返回闲聊响应
```

### 5.2 登录后：部门大脑路径（文字）

```
用户输入（文字）
    │
    ▼
/ws/dept/{department}
    │
    ▼
DepartmentWebSocketHandler.handleChatMessage()
    │
    ├─ 鉴权 + 部门访问校验
    │
    ▼
agentService.startSession(sessionId, accessLevel, department)
    │
    ▼
AgentService.processTextAsync() — 通道感知路由
    │
    ├─ channel=public（未登录）
    │   → ChatNeuronRouter.route() — 闲聊神经元处理
    │
    ├─ channel=department/*（已登录）
    │   → 绕过 ChatNeuronRouter！
    │   → 直接调用部门大脑 LLM（意图分类由 LLM 处理）
    │   → coordinator.publishUserInput() → 部门大脑
    │   → coordinator 响应通道 → 返回结果
    │
    └─ 无 coordinator 兜底
        → ModelManager.processChatWithIntent() → LLM API
```

### 5.3 登录后：部门大脑路径（语音）

```
用户按住说话 → 前端录音 → Opus 编码 → Base64
    │
    ▼
WebSocket 发送 "audio_full" 类型消息 → AgentWebSocketHandler
    │
    ▼
AgentService.processAudioFullChain() — 独立语音链路
    │
    ├─ 1. Base64 解码
    │
    ├─ 2. AudioNative.Processor.decodeOpus()     ← Rust JNI (opus_codec.rs)
    │      Base64 Opus → 解码 → PCM 音频
    │
    ├─ 3. savePcmToWav()
    │      PCM → 临时 WAV 文件
    │
    ├─ 4. modelManager.recognizeSpeech()         ← Sherpa-ONNX ASR
    │      WAV 文件 → 识别 → 文本
    │
    ├─ 5. modelManager.processChatWithIntent()    ← 意图分类 + LLM 处理
    │      语音不经过 ChatNeuronRouter，直接调用 LLM
    │
    ├─ 6. modelManager.synthesizeSpeechRaw()      ← MeloTTS
    │      响应文本 → 合成 → PCM 音频
    │
    ├─ 7. AudioNative.Processor.encodePcm()       ← Rust JNI (opus_codec.rs)
    │      PCM → 编码 → Opus 包
    │
    └─ 8. Base64 编码 → WebSocket 返回 → 前端解码播放
```

**Rust JNI 音频编解码核心文件**：
- `living-agent-native/src/audio/opus_codec.rs` — Opus 编解码器实现
- `living-agent-native/src/jni/audio_jni.rs` — JNI 绑定
- `AudioNative.Processor` — Java 侧 JNI 调用入口

## 6. 权限与入口矩阵（登录状态 × 身份 × 页面 × 通道）

| 登录状态 | 身份 | 主要页面 | 可见对话按钮/入口 | 允许通道 | 语音 | 说明 |

## 7. 关键业务结论

1. **登录前统一闲聊**：任何人未登录时都只能使用闲聊能力，不区分身份、部门。

2. **登录后统一部门大脑**：登录后不再有闲聊入口，统一通过部门大脑对话；董事长可访问所有部门，其他仅限本部门。

3. **语音由前端控制**：语音功能的开启/关闭由前端对话页面的开关控制，开启后调用 Python Daemon 的 ASR/TTS 能力。

4. **固定员工不可直连**：所有人都不允许直接跟"固定数字员工"对话，固定员工的使用场景统一收口到部门大脑。

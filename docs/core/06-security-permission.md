# 安全与权限

> 企业级安全与权限管理系统
>
> 本文档补充说明：
> - 权限检查先于路由与执行
> - AccessLevel 作为资源总闸门
> - Public / Department / Admin API 分类
> - WebSocket / 沙箱 / 审计 / 合规的边界

## 一、权限隔离架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    权限隔离架构                                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  权限检查在路由之前执行：                                                      │
│  ├── CHAT_ONLY (离职/外来) → 只能到 Qwen3Neuron                              │
│  │   └── 无法访问 MainBrain、部门大脑、企业知识库                             │
│  │                                                                           │
│  ├── LIMITED (试用期/客户/伙伴) → 受限访问                                    │
│  │   └── 可访问: Qwen3Neuron, AdminBrain, CsBrain                            │
│  │                                                                           │
│  ├── DEPARTMENT (在职员工) → 本部门完整功能                                   │
│  │   └── 可访问: Qwen3Neuron, ToolNeuron, 本部门大脑                         │
│  │                                                                           │
│  └── FULL (董事长) → 所有资源                                                │
│      └── 可访问: 所有神经元和大脑 + MainBrain                                 │
│                                                                             │
│  模型选择说明:                                                               │
│  - 所有层级的模型都通过 BrainModelResolver + ModelPoolManager 动态选择       │
│  - 模型选择基于模型健康状态、硬件资源、任务复杂度                              │
│  - 不再硬编码具体模型名称                                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 二、访问级别定义

| 级别 | 权限范围 | 可访问资源 |
|------|----------|-----------|
| **CHAT_ONLY** | 仅闲聊，禁止企业资源 | 动态选择(闲聊模型) |
| **LIMITED** | 部分大脑，禁止敏感知识 | 动态选择(受限模型), AdminBrain, CsBrain |
| **DEPARTMENT** | 本部门完整功能 | 动态选择(部门模型), ToolNeuron, 本部门大脑 |
| **FULL** | 所有大脑和工具 | 动态选择(全功能模型), 所有大脑 + MainBrain |

## 三、用户身份与权限映射

| 身份 | 访问级别 | 模型选择 | 特殊说明 |
|------|----------|----------|---------|
| 董事长 | FULL | 动态选择(全功能模型) | 可跨部门协调 |
| 在职员工 | DEPARTMENT | 动态选择(部门模型) | 仅本部门 |
| 试用期员工 | LIMITED | 动态选择(受限模型) | 受限访问 |
| 离职员工 | CHAT_ONLY | 动态选择(闲聊模型) | 仅闲聊 |
| 外来访客 | CHAT_ONLY | 动态选择(闲聊模型) | 仅闲聊 |
| 客户 | LIMITED | 动态选择(受限模型) | 受限访问 |
| 合作伙伴 | LIMITED | 动态选择(受限模型) | 受限访问 |

> 注: 所有模型都通过 BrainModelResolver + ModelPoolManager 动态选择，不再硬编码具体模型名称。

## 七、安全沙箱

### 7.1 沙箱配置

```java
public class SandboxConfig {
    // 资源限制
    private long maxMemory;           // 最大内存 (MB)
    private long maxCpuTime;          // 最大CPU时间 (ms)
    private long maxExecutionTime;    // 最大执行时间 (ms)
    
    // 网络限制
    private boolean allowNetwork;     // 是否允许网络访问
    private List<String> allowedHosts; // 允许访问的主机
    
    // 文件系统限制
    private boolean allowFileSystem;  // 是否允许文件系统访问
    private List<String> allowedPaths; // 允许访问的路径
    
    // 命令黑名单
    private List<String> commandBlacklist;
}
```

## 八、数据安全

### 8.1 敏感数据处理

| 数据类型 | 处理方式 | 存储位置 |
|---------|---------|---------|
| 员工密码 | 哈希存储 (BCrypt) | PostgreSQL |
| 声纹特征 | 向量加密存储 | Qdrant |
| API密钥 | 加密存储 | 环境变量/密钥管理系统 |
| 对话记录 | 分级存储 | SQLite/PostgreSQL |

### 8.2 审计日志

| 事件类型 | 记录内容 | 保留期限 |
|---------|---------|---------|
| 登录/登出 | 用户ID、时间、IP、结果 | 1年 |
| 权限变更 | 操作人、目标用户、变更内容 | 3年 |
| 数据访问 | 访问者、数据类型、操作 | 1年 |
| 系统配置 | 修改人、配置项、旧值/新值 | 3年 |

## 九、合规管理

### 9.1 合规检查项

| 检查项 | 频率 | 处理方式 |
|--------|------|---------|
| 数据保留期限 | 每日 | 自动清理过期数据 |
| 权限审查 | 每月 | 生成报告，人工审核 |
| 访问日志审计 | 实时 | 异常检测，自动告警 |
| 敏感数据扫描 | 每周 | 发现敏感数据，加密处理 |

### 9.2 合规报告

```
合规报告内容:

├── 权限分配情况
├── 安全事件记录
├── 审计日志摘要
└── 改进建议
```

## 十、补充治理资料对应关系

- `documents/_meta/access-rules.md` 与 `documents/_meta/naming-conventions.md` 为权限、身份、命名提供统一规则来源。
- `documents/shared/governance/06-security-governance.md` 是本章节治理落点，应与 API、WebSocket、工具、沙箱、审计口径一致。
- `documents/shared/company/requirement-clarification-rules.md`、`requirement-routing-state-machine.md`、`demand-routing-status-machine.md` 等说明：在需求/任务路由阶段就应完成权限与风险识别，不能把高风险请求带到执行层再处理。
- `documents/shared/company/hr-15-founder-enterprise-system.md` 进一步说明董事长专属权限与跨部门协调边界。

## 十一、建议修补点

- 明确 `AccessLevel` 是资源总闸门，不只是局部标签
- 明确所有入口"先身份识别，再权限判断，再路由执行"
- 明确 Public / Department / Admin 三类 API
- 明确 WebSocket 通道权限与部门/级别绑定
- 明确审计字段与合规报告字段统一
- 确认模型选择不再硬编码，使用模型池动态选择

## 十二、结论

安全与权限体系已经有核心实现，但必须与企业治理文档、需求路由规则、部门职责和通道模型统一起来，才能真正避免"入口各自解释权限"的问题。安全不是附属能力，而是企业生命体的门禁与边界。

模型选择通过动态模型池机制，不再硬编码具体模型名称，所有模型通过 BrainModelResolver + ModelPoolManager 自动选择可用模型。

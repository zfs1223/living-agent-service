### P0-2 自治编排主流程闭环

**目标**  
打通从用户输入到最终总结的完整自治执行链。

**主链路**
`用户输入 → 意图分析 → 需求就绪评估 → 主脑规划 → 部门路由 → 员工分派 → 执行 → 回执 → 总结 → 沉淀`

**任务拆解**
- [x] 确认唯一自治入口，不允许 Controller / Service / WebSocket 各自起一套平行流程。
- [x] 统一入口数据模型，明确对话、任务、项目、执行、回执的主键关联。
- [x] 明确需求不清晰时的澄清分支。
- [x] 明确任务无法归一到执行能力时的人工接管分支。
- [x] 明确员工执行失败时的重试、换人、升级逻辑。
- [x] 明确执行完成后如何进入总结与知识沉淀。
- [x] 明确 Trace 的每个阶段记录什么字段。

**依赖**
- `DialogueAnalyzer`
- `RequirementReadinessEvaluator`
- `MainBrainTaskDirector`
- `FixedEmployeeDispatcher`
- `EmployeeTaskExecutor`
- `EmployeeExecutionReceiptService`
- `MainBrainFinalSummaryService`

**验收标准**
- 给定一个任务请求，能完整走到最终回复或明确澄清。
- 中间任一环失败后，有明确的退出路径。
- Trace 可回放整个过程。

## 建议执行顺序

1. 先做 `P0`：清理结构和主流程断链。
2. 再做 `P1`：把核心模块真正串起来。
3. 然后做 `P2`：提升稳定性、性能和可维护性。
4. 最后做 `P3`：降低协作成本。

## 最终判定标准

只有同时满足以下条件，才能认为某个模块“完全落地”：

- 有明确入口
- 有统一输入输出
- 有状态机
- 有失败分支
- 有审计或 Trace
- 有持久化或回收
- 有权限边界
- 能与其它模块串成闭环

如果缺任一项，就只能算“能力存在”，不能算“流程落地”。

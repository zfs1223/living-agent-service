# 员工入职与转正离职管理制度

> **制度编号**：HR-01
> **制定部门**：人力资源部
> **版本**：v1.0
> **生效日期**：2026-04-14

---

## 1. 制度目的

本文档定义企业生命智能体中人类员工的入职、转正、离职全生命周期管理规范，确保员工与数字员工的协同运转符合核心框架设计。

## 2. 适用范围

- 所有在编人类员工
- 试用期员工
- 实习生、访客等特殊身份

**不适用于**：数字员工（数字员工管理见 `01-employee-governance.md`）

## 4. 入职管理

### 4.1 入职流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           入职办理流程                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【步骤1：Offer确认】                                                      │
│  候选人接受Offer → HR录入基本信息                                         │
│                                                                             │
│  【步骤2：账号开通】                                                      │
│  ├── 创建员工账号（employee://human/{provider}/{accountId}）              │
│  ├── 绑定初始岗位                                                        │
│  ├── 配置访问级别（AccessLevel）                                          │
│  └── 分配部门归属                                                        │
│                                                                             │
│  【步骤3：系统初始化】                                                    │
│  ├── 开通企业身份认证（OAuth/钉钉/飞书等）                                │
│  ├── 创建会话上下文（AuthContext）                                        │
│  └── 分配基础工具权限                                                    │
│                                                                             │
│  【步骤4：培训与上岗】                                                    │
│  ├── 系统使用培训                                                        │
│  ├── 数字员工协作培训                                                    │
│  └── 部门融入                                                            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 入职字段映射

根据 `03-employee-model.md` §3，入职信息需完整录入以下字段：

| 字段层级 | 字段名 | 说明 | 必填 |
|---------|--------|------|------|
| 身份层 | `employeeId` | 唯一标识，格式`employee://human/{provider}/{accountId}` | 是 |
| 身份层 | `employeeType` | 固定值`HUMAN` | 是 |
| 身份层 | `authId/provider` | 认证提供商与账号 | 是 |
| 组织层 | `department` | 所属部门代码 | 是 |
| 组织层 | `roles` | 岗位角色列表 | 是 |
| 组织层 | `managerId` | 直接主管ID | 是 |
| 治理层 | `accessLevel` | 初始为`LIMITED`（试用期） | 是 |
| 治理层 | `identity` | 身份标识，如`INTERNAL_PROBATION` | 是 |

## 5. 转正管理

### 5.1 转正流程

```
发起人：直属主管
    │
    ▼
提交转正申请
├── 试用期表现评估
├── 绩效数据汇总
├── 数字员工协作评价
└── AccessLevel变更申请
    │
    ▼
HR审核
├── 资质核实
├── 权限变更确认
└── 薪资调整核定
    │
    ▼
系统执行
├── AccessLevel: LIMITED → DEPARTMENT
├── 权限刷新
├── 在线会话通知
└── 审计记录
    │
    ▼
转正生效
```

### 5.2 AccessLevel变更

| 变更前 | 变更后 | 权限变化 |
|-------|-------|---------|
| `LIMITED` | `DEPARTMENT` | 解锁本部门完整功能 |

**转正后权限变化**：
- 解锁本部门全部工具权限
- 解锁本部门L2知识库读写
- 可参与半自动流程审批
- 可调度本部门数字员工

## 6. 岗位变更管理

### 6.1 岗位变更类型

| 变更类型 | 说明 | AccessLevel变化 |
|---------|------|----------------|
| 调岗 | 部门或岗位调整 | 可能不变或调整 |
| 晋升 | 职级提升 | 通常提升 |
| 降级 | 职级下降 | 通常下降 |
| 借调 | 临时支援其他部门 | 临时扩展 |

### 6.2 岗位变更即时生效

根据核心框架 `01-employee-governance.md` §6.1，岗位变更必须即时生效：

```
【生效规则】
✗ 不做延迟批处理
✗ 不依赖后台定时刷新
✓ 变更后立即生效

【变更后必须处理】
1. 刷新权限缓存
2. 通知在线会话
3. 写审计记录（PERM_POSITION_CHANGED）
4. 确保新入口立即可见
```

### 6.3 跨部门调动

```
【调动流程】
1. 发起调动申请（原部门负责人 + 新部门负责人会签）
2. HR审核编制与权限
3. 系统执行变更
4. 更新部门归属
5. 刷新工具授权范围

【权限调整】
原部门工具 → 移除
新部门工具 → 添加
共享工具 → 保留
```

## 7. 离职管理

### 7.1 离职类型

| 类型 | 说明 | AccessLevel变更 |
|------|------|----------------|
| 主动离职 | 员工申请 | LIMITED（受限） |
| 被动离职 | 公司解除 | CHAT_ONLY（仅聊天） |
| 退休 | 到达法定年龄 | CHAT_ONLY |
| 实习结束 | 实习期届满 | 账号冻结 |

### 7.2 离职流程

```
发起人：员工/HR
    │
    ▼
离职申请
├── 工作交接
├── 资产归还
├── 权限核查
└── 数字员工任务转移
    │
    ▼
HR审核
├── 离职手续办理
├── 薪资结算
└── 证明开具
    │
    ▼
系统执行
├── AccessLevel: → CHAT_ONLY
├── 会话冻结
├── 工具权限移除
└── 部门归属变更
    │
    ▼
离职生效
```

### 7.3 权限回收检查清单

| 检查项 | 说明 | 必须完成 |
|-------|------|---------|
| 账号状态 | 变更为INACTIVE | 是 |
| AccessLevel | 降级为CHAT_ONLY | 是 |
| 会话清理 | 强制下线所有在线会话 | 是 |
| 工具权限 | 移除所有工具授权 | 是 |
| 知识库 | 移除L2/L3写入权限 | 是 |
| 群组 | 退出所有工作群组 | 是 |
| 项目 | 转移在执行项目 | 是 |
| 数字员工 | 重新分配托管的数字员工 | 是 |

### 7.4 离职后数据保留

```
【数据保留策略】
├── 工作产出：保留3年（按合规要求）
├── 通讯记录：保留1年
├── 绩效数据：保留5年
├── 数字员工交互记录：按项目周期保留
└── 审计日志：保留7年（法定要求）
```

## 8. 特殊身份管理

### 8.1 实习生

| 管理项 | 规范 |
|-------|------|
| AccessLevel | CHAT_ONLY |
| 工具权限 | 仅限基础工具 |
| 知识库 | 仅L1私有 |
| 合同期限 | 最长6个月 |
| 转正路径 | 需重新入职流程 |

### 8.2 外部访客

| 管理项 | 规范 |
|-------|------|
| AccessLevel | CHAT_ONLY |
| 有效期限 | 最长30天 |
| 通道限制 | 仅public通道 |
| 审计要求 | 全操作审计 |

### 8.3 独立董事/外部顾问

| 管理项 | 规范 |
|-------|------|
| AccessLevel | FULL（受限） |
| 工具权限 | 按需分配 |
| 知识库 | L3全局只读 |
| 审计要求 | 强审计 |

## 9. 审计要求

### 9.1 必须审计的事件

| 事件 | 审计级别 | 字段 |
|------|---------|------|
| 入职 | 中审计 | actor, target, department, role, timestamp |
| 转正 | 中审计 | actor, target, before/after AccessLevel, timestamp |
| 调岗 | 中审计 | actor, target, change_type, before/after, timestamp |
| 离职 | 强审计 | actor, target, reason, permissions_reclaimed, timestamp |

### 9.2 审计字段标准

根据 `01-employee-governance.md` §9，审计记录必须包含：

```json
{
  "actor": "HR负责人employeeId",
  "employee_origin": "human",
  "department": "HR部门",
  "role": "hr_manager",
  "action": "HUMAN_EMPLOYEE_ONBOARDED",
  "target": "新员工employeeId",
  "trace_id": "链路追踪ID",
  "timestamp": "操作时间",
  "details": {
    "department": "目标部门",
    "position": "岗位",
    "access_level_before": "变更前",
    "access_level_after": "变更后"
  }
}
```

# 需求澄清规则

## 1. 触发条件

当需求满足以下任一条件时，进入澄清状态：

- 目标不明确
- 范围不明确
- 交付标准缺失
- 预算缺失
- 截止时间缺失
- 需求过大且未拆分
- 涉及多个部门但未说明协作边界
- 存在明显冲突或风险

## 2. 澄清问题模板

系统应优先返回以下问题：

- 这个需求最终要解决什么问题？
- 交付完成后，什么结果算成功？
- 需要在什么时候完成？
- 是否有预算或资源上限？
- 这次需求的范围边界是什么？
- 是否允许分阶段交付？
- 是否有必须避开的限制？
- 是否已有相关参考材料？

## 3. 澄清策略

### 3.1 轻度不规范

如果只是缺少少量信息：

- 自动提示缺失项
- 允许补充后继续

### 3.2 中度不规范

如果需求范围太大或冲突较多：

- 生成澄清单
- 暂停进入评估
- 需要董事长补充或缩小范围

### 3.3 高风险不规范

如果涉及合同、付款、权限、生产变更、敏感数据：

- 立即升级人工审批
- 不允许自动执行
- 提示风险原因

## 4. 澄清结果

澄清结果必须明确输出：

- 是否可继续评估
- 缺失了哪些信息
- 建议补充内容
- 是否需要人工介入

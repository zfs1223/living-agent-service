# 创始人/董事长制度

**制度编号**: HR-15

**版本**: v1.0

**最后更新**: 2026-04-14

---

## 1. 目的与范围

### 1.1 目的

本制度定义企业生命智能体中创始人/董事长的特殊治理地位、权限边界与责任义务。一人公司模式下，创始人是唯一拥有 FULL 权限的人类员工，承担公司战略决策与数字员工整体管理的双重职责。

### 1.2 适用范围

- 公司创始人
- 董事长
- 实际控制人

### 1.3 特殊定位

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           一人公司治理结构                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【创始人/董事长】                                                         │
│  ├── 唯一 FULL 权限持有者                                                 │
│  ├── 战略决策最终责任人                                                   │
│  ├── 数字员工整体管理者                                                   │
│  └── 企业知识资产最终负责人                                               │
│                                                                             │
│  【MainBrain】                                                             │
│  ├── 跨部门协调核心                                                       │
│  ├── 战略任务执行                                                          │
│  └── 向董事长汇报                                                          │
│                                                                             │
│  【部门大脑】                                                              │
│  ├── 各部门数字员工协调                                                    │
│  └── 向 MainBrain 汇报                                                     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3. 权限体系

### 3.1 FULL 权限范围

> 依据《06-安全权限》§3 访问级别定义

创始人拥有的 FULL 权限包括：

| 权限维度 | 具体权限 |
|---------|---------|
| 通道访问 | 全部通道（channel://*） |
| 知识访问 | L1/L2/L3 全部层级 |
| 工具执行 | 全部工具（含 claude_cli） |
| 数字员工管理 | 创建/配置/调度/淘汰 |
| 部门管理 | 部门创建/合并/解散 |
| 战略决策 | 公司战略、业务方向 |
| 财务审批 | 无上限审批 |

### 3.2 权限使用约束

虽然拥有 FULL 权限，但创始人应遵循以下约束：

1. **最小授权原则**：日常操作尽量使用 DEPARTMENT 权限
2. **审批留痕**：重大决策需记录到知识库（L3）
3. **安全隔离**：涉密操作使用独立会话
4. **审计配合**：定期接受系统安全审计

## 4. 职责与义务

### 4.1 核心职责

```
【战略层面】
├── 定义企业使命、愿景、价值观
├── 制定公司战略规划
├── 决策业务发展方向
├── 审批重大投资与预算
└── 评估公司整体绩效

【数字员工管理】
├── MainBrain 部署与优化
├── 部门大脑能力规划
├── 数字员工编制审批
├── 数字员工进化决策
└── 数字员工绩效评估

【知识管理】
├── L3 全局知识最终审批
├── 企业知识资产保护
├── 知识分类策略制定
└── 知识共享政策制定

【组织治理】
├── 制定公司制度
├── 审批部门职责
├── 决策组织架构
└── 监督制度执行
```

### 4.2 决策流程

```
日常决策 (< 1小时)
└── 创始人直接决策

重要决策 (需记录)
└── 创始人决策 → 记录到 L3 知识库

战略决策 (需规划)
└── MainBrain 辅助分析 → 创始人决策

紧急事件 (需响应)
└── MainBrain 评估 → 创始人授权 → 执行
```

## 5. 与 MainBrain 的协作

### 5.1 MainBrain 定位

MainBrain 是创始人的核心助手，依据《02-核心架构》§3.1：

```
MainBrain 职责
├── 跨部门协调与复杂任务分解
├── 战略任务编排与执行
├── 向董事长汇报关键进展
└── 协调部门大脑协作
```

### 5.2 协作模式

| 协作场景 | 协作方式 |
|---------|---------|
| 战略规划 | MainBrain 分析 → 创始人决策 |
| 任务分配 | 创始人指令 → MainBrain 编排 → 部门大脑执行 |
| 绩效评估 | MainBrain 汇总 → 创始人审核 |
| 危机处理 | MainBrain 预警 → 创始人授权 → 执行 |

### 5.3 MainBrain 配置

| 配置项 | 值 |
|-------|-----|
| 模型 | Qwen3.5-27B (云端API) |
| 权限 | FULL |
| 知识范围 | L1/L2/L3 全部 |
| 通道权限 | channel://enterprise/main, channel://dispatch/* |

## 6. 数字员工整体管理

### 6.1 编制管理

创始人审批数字员工编制：

| 类型 | 审批权限 |
|------|---------|
| 新部门数字员工 | 创始人审批 |
| 部门内增加实例 | 部门大脑申请 → 创始人备案 |
| 数字员工淘汰 | 部门大脑申请 → 创始人审批 |

### 6.2 进化决策

依据《05-进化系统》§4，创始人对以下进化决策拥有审批权：

| 进化类型 | 决策层级 |
|---------|---------|
| REPAIR | 部门大脑自动处理 |
| OPTIMIZE | 部门大脑自动处理 |
| INNOVATE | 创始人审批 |
| ESCALATE | 创始人决策 |

### 6.3 绩效评估

创始人最终审批数字员工整体绩效评估结果。

## 7. 风险管控

### 7.1 安全风险

| 风险类型 | 防控措施 |
|---------|---------|
| 权限滥用 | 最小授权原则 + 操作审计 |
| 单点故障 | 关键任务设置备份数字员工 |
| 数据泄露 | 涉密操作隔离 + 加密存储 |

### 7.2 运营风险

| 风险类型 | 防控措施 |
|---------|---------|
| 决策失误 | MainBrain 辅助分析 + 知识库参考 |
| 效率瓶颈 | 合理分配任务给数字员工 |
| 知识断层 | 重要决策记录到 L3 知识库 |

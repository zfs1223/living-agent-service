# 通道通信治理

> 对齐项目核心框架 `02-core-architecture.md`，定义企业生命智能体中通道通信子系统的治理规范。

## 1. 通道子系统架构

根据 `02-core-architecture.md` §3.2：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           通道子系统架构                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【ChannelManager】                                                        │
│  消息发布/订阅与通道治理                                                   │
│                                                                             │
│  【标准通道模式】                                                          │
│  广播、单播、优先级、轮询                                                  │
│                                                                             │
│  【命名规范】                                                              │
│  channel://{scope}/{session-or-domain}                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 通道ID规范

根据 `02-core-architecture.md` §3.2、`03-employee-model.md` §5：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              通道ID规范                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【命名格式】                                                              │
│  channel://{scope}/{name}                                                 │
│                                                                             │
│  【scope范围】                                                            │
│  ├── enterprise   - 企业级                                                  │
│  ├── department  - 部门级                                                 │
│  ├── project     - 项目级                                                 │
│  ├── perception  - 感知通道                                               │
│  ├── dispatch    - 路由分发                                                │
│  └── response    - 响应通道                                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 标准通道定义

| 通道ID | 范围 | 用途 | 访问控制 |
|--------|------|------|---------|
| `channel://enterprise/main` | 企业级 | 全员广播 | 全体员工 |
| `channel://department/{dept}` | 部门级 | 部门内部沟通 | 部门成员 |
| `channel://project/{projectId}` | 项目级 | 项目协作 | 项目成员 |
| `channel://perception/{sessionId}` | 会话级 | 感知消息 | 会话参与者 |
| `channel://dispatch/{sessionId}` | 会话级 | 路由分发 | 系统内部 |
| `channel://response/{sessionId}` | 会话级 | 响应返回 | 请求者 |

## 3. 消息格式

根据 `02-core-architecture.md` §4 关键组件：

```
ChannelMessage（神经元通信消息载体）
├── 消息类型：文本/音频/控制/系统
├── 发送者：employeeId
├── 接收者：channelId
├── 内容：消息体
├── 元数据：timestamp, traceId
└── 扩展：attachments, metadata
```

## 4. 通道隔离原则

根据 `06-security-permission.md` §4：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           通道隔离原则                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【部门级隔离】                                                            │
│  非授权身份不得订阅或发布部门敏感通道                                        │
│                                                                             │
│  【知识隔离】                                                              │
│  按L1/L2/L3作用域与身份联合控制                                             │
│                                                                             │
│  【工具隔离】                                                              │
│  工具执行需通过Hook与策略检查                                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 5. 会话隔离

根据 `02-core-architecture.md` §3.2：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           会话隔离机制                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【会话通道命名】                                                          │
│  channel://perception/{sessionId}   - 感知通道                           │
│  channel://dispatch/{sessionId}     - 路由分发                            │
│  channel://response/{sessionId}     - 响应通道                            │
│                                                                             │
│  【隔离原则】                                                              │
│  每个会话拥有独立的感知、分发、响应通道                                     │
│  会话结束后通道资源释放                                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

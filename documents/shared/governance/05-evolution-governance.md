## 4. 执行策略

根据 `05-evolution-system.md` §4：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           执行策略定义                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【REPAIR】修复现有能力（以稳定性优先）                                     │
│                                                                             │
│  【OPTIMIZE】优化现有能力（以效率优先）                                     │
│                                                                             │
│  【INNOVATE】新增能力（以边界约束优先）                                    │
│  ⚠️ 必须具备验证门禁与回滚策略                                             │
│                                                                             │
│  【DEFER】延迟决策（证据不足）                                             │
│                                                                             │
│  【ESCALATE】人工接管（高风险或高影响）                                     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 策略选择矩阵

| 场景 | 推荐策略 | 原因 |
|------|---------|------|
| 现有能力出现故障 | REPAIR | 修复优先 |
| 性能下降 | OPTIMIZE | 优化优先 |
| 新业务需求 | INNOVATE | 新增能力 |
| 信号不明确 | DEFER | 延迟决策 |
| 高风险操作 | ESCALATE | 人工接管 |
